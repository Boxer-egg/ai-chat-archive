# 竞品调研：AI 对话归档/导出工具对比

> 调研日期：2026-11-19　|　方法：GitHub 搜索（按 star 排序）+ README/源码速览
> 目的：确认本项目差异化定位，筛选可借鉴的用户体验与输出层设计

| **DeepSeek/Kimi/Grok 归档工具** | — | **搜索为零** | — | — | **市场空白** |

**三个结构性观察**：

1. **几乎全部是"手动导出"**——没有主流工具做"自动持续归档"。用户必须记得点按钮，漏点是常态。
2. **几乎全部是"单平台 + 一次性文件"**——导出完是一堆文件，没有本地可搜索的数据库；跨平台统一归档无人做。
3. **国产平台是空白**——DeepSeek/Kimi/Grok 没有任何有 star 的归档工具，而它们的用户量巨大。

## 2. 用户视角对比（最重要）

| 维度 | pionxzh (userscript) | socketteer (扩展) | to-notion | **本项目** |
| --- | --- | --- | --- | --- |
| 安装门槛 | **高**：装 Tampermonkey 再装脚本，非技术用户易放弃 | 低：商店扩展 | 中：装扩展 + 授权 Notion 账号 | 中：开发者模式加载解压包（上架商店后变低） |
| 使用方式 | 每次手动点"导出"菜单 | 每次手动点导出按钮 | 手动保存单条到 Notion | **全自动**：开着页面就在存，弹窗看状态 |
| 平台覆盖 | 只 ChatGPT | 只 Claude | 只 ChatGPT | **5 平台**（含国产 3 家） |
| 数据形态 | 一次性文件（MD/PNG/JSON） | 一次性 ZIP | 存在 Notion（云端） | **本地 IndexedDB 库**：列表/详情/搜索/再导出 |
| 隐私 | 本地 ✓ | 本地 ✓ | **上传 Notion 服务器 ✗**（数据出机） | **本地 ✓ + 零上传红线**（ESLint 强制禁网络 API） |
| 数据主权 | 文件在自己手里 | 文件在自己手里 | 依赖 Notion 存续与账号 | 完全在本地，JSON 备份随时导出 |
| 历史补录 | 无（只导当前可见） | 无 | 无 | **滚动到哪补到哪**，Myers diff 对齐去重 |
| 多账号 | 无概念 | 无概念 | 无概念 | **账号指纹分桶**，换号不串数据 |
| 平台改版韧性 | 作者活跃，修得快 | 已停更，坏了没人修 | 活跃 | 每平台独立适配器 + 自检降级 + 夹具回归测试 |
| 离线可用 | 导出后可离线 | 导出后可离线 | 需联网（Notion） | **完全离线可用** |

**用户体验结论**：本项目的核心便利性是"**无感**"——用户不用记得点任何按钮，对话自动进本地库，随时搜索/导出；这是所有竞品都没有的形态。当前主要短板是**安装门槛**（未上架 Chrome 商店，需开发者模式手动加载）和**单条导出文件名不带标题**（见 §4）。

## 3. 头部项目逐个点评

### pionxzh/chatgpt-exporter（2894★，绝对头部）

- **为什么赢**：格式最全（text / PNG 截图 / MD / HTML / JSON——JSON 还兼容 OpenAI 官方格式与 SillyTavern/Ooba）、功能打磨细（图片 omit/link/zip 三模式、数学公式保护、文件名模板变量、meta 开关、分享页与 temporary chat 支持）、作者持续维护。
- **局限**：userscript 形态门槛高；只支持 ChatGPT；手动触发；采集依赖 MAIN world 权限（读 `unsafeWindow.__reactRouterContext` + 内部 API），MV3 内容脚本的隔离世界做不到这条路。
- **对本项目**：**输出层细节的宝库**，采集层无可借鉴（违反零上传/最小权限红线）。

### socketteer/Claude-Conversation-Exporter（135★，形态最接近本项目）

- **亮点**：
  - **模型信息保留**——官方 Claude 导出没有模型字段，它保留每条消息的模型，还能对历史"默认模型"会话按时间线推断实际模型。对"这段回答到底是哪个模型给的"场景价值很高。
  - **branch-aware**——Claude 对话有分支编辑，只导出当前分支，不混入废弃分支。
- **局限**：手动、单平台、已停更半年。
- **对本项目**：模型信息保留**直接可借鉴**（加 `model?` 字段）；branch-aware 行为本项目天然正确（只采 DOM 可见内容），值得在文档写明。

### chatgpt-to-notion 类（笔记同步路线）

- 满足"把对话整理进知识体系"的需求，但数据上传第三方服务器，与"本地归档"的目标用户不同。不借鉴，作差异化对照。

### ezwep / HumainLabs（全量备份路线）

- 走官方 API（需要 token/cookie），能备份全部历史包括 projects，但要碰凭证、依赖 API 存续，商店审核敏感。HumainLabs 已停更。**验证了我们"只读页面可见信息"路线的可持续性**。

## 5. 定位结论

- **无人做"自动持续归档 + 多平台 + 本地可搜索库"**——本项目的形态在市场上是独一份，空白主要在国产平台。
- 竞品的用户痛点集中在：手动易漏、文件散乱不可搜索、单平台、数据要出机。本项目四项全对，差异化清晰。
- 最大体验短板是**安装门槛**（未上架商店）——这是发布运营问题，不是技术问题。
- 近期最值得做的是 §4 的 #1（模型字段）和 #2（文件名带标题），都是小改动、直接提升用户使用便利。
